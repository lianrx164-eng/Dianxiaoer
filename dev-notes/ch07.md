## 阶段 0 · brainstorm 前的 recon

**用户关键原话**

- 「我要用 Superpowers 模式让客服在一通会话里记得住前面聊过什么,把第一版的简单裁剪升级成正经的上下文管理。只管当前会话,不跨会话、不存用户画像。」
- 「三层结构……最近的留原文,一个字都不压;中间一层按规则截短……最远的异步压成一段段梗概。两个锚点……降级只挪这两个 id、不搬数据。」
- 「梗概一段段攒、压完不回头重写,旧梗概只作背景给模型看、不参与合并。」
- 「早期梗概和检索证据合成一条挂在用户这句之后。梗概不许单独占一条 system。」
- 「token 预算从模型窗口倒推……中文按字数折 token 的口径要和预算一起校准。」

**关键产出**

- 读桌面 `CH_07/Sepc.md`、`Plan.md`、`ch_07.sql`;读本仓 ch06 基线(`nodes.py`、`runtime.py`、`memory.py`、`repository.py`、`models.py`、`index.html`、`conftest.py`、既有测试)。
- 识别出桌面 Spec/Plan 是「第一步:双层 + 滚动摘要」,本轮需求 + SQL 第二步是「三层 + 分段追加摘要」;两者在层数、触发条件、摘要合并方式上互斥。
- 产出设计文档:`docs/superpowers/specs/2026-11-14-ch07-context-management-design.md`。

**拒绝/纠偏**

- 拒绝按桌面 Plan 的「入口写 user 消息 + State 里 `db-{msg_id}` 锚点」实现:本仓 user/assistant 统一在 `log_node` 落库,并有「失败轮不落 MySQL」测试;改为每轮入口读 `list_dialog_messages`,用 DB 行 + 本轮 State 切片拼精简版。边界仍是 DB id,双轨不变。
- 拒绝桌面 Plan 的 `summary_trigger_messages=30` 条数触发:按用户要求改为层 2 渲染 token 超预算触发。
- 拒绝桌面 Plan 的「旧摘要 + 新段滚动重写」:改为 `conversation_summaries` 一段一行只追加;`conversations.summary` 降级为最近几段投影。
- 拒绝把摘要拼进 system:system 恒为 `AGENT_SYSTEM`,梗概 + 证据 + 退款数据合成一条 `HumanMessage` 挂当前用户之后。

**翻车与返工**

- 暂无代码改动。预算公式最初只对上了「演示配置 5650」,对不上「只调窗口会归零」;把证据按 `rerank_top_k × 400`、ReAct 峰值按 `max_agent_steps × tool_result_max_tokens` 建模后,两组数值同时吻合,反证了常量拆分(见 spec §7)。
