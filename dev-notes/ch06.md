**关键原话**:「我要用 Superpowers 模式把客服系统里占位的分流器做成正式版,这是 Workflow 里最关键的节点。」七条需求:指代消解+Query 改写合一、Query 扩写(严格 3 条、只退款售后)、意图四件套(8 类含「其他」+ confidence)、退款/售后确定性子流程、槽位处理(缺单弹选择器、退款原因固定下拉)、前端订单卡片+退款表单、意图模型先求准+降级路只落配置种子。

**产出**:
- spec:`docs/superpowers/specs/2026-11-14-ch06-intent-recognition-design.md`
- 分支:`ch06-intent-recognition`

**纠偏(与桌面 Spec/Plan 的差异,已写进 spec §2)**:
- 桌面文档假设基线节点名 `resolve_reference / retrieve_knowledge / main_agent`,本仓 ch05 实际是 `coref / forced_rag / agent_llm`。保留本仓名字,只把 `coref` 做实;新增 `fetch_order / retrieve_policy / script_reply`。行为与验收不变。
- 桌面 Plan 的 `docker compose` / `make milvus-up` / `.venv/bin/python` 在本仓不存在(Windows + Milvus Lite + `uv run`),命令全部改写。
- 桌面 Plan 用裸 `with_structured_output`;本仓统一 `structured_model`(DeepSeek 思考模式会 400),意图/扩写都走统一入口。
- 桌面 Plan 的闲聊文案「我暂时还不会回答这个」对「你好呀」不合适;沿用 ch05 已有问候语(已含「引回产品」),只新增「其他」文案。
- 桌面 Plan 未覆盖「暂停中用户又发新消息」。实测 langgraph 1.2.21:新输入会被接受、再次触发同一中断、新消息不处理。定为 D9:runtime 检测未决中断时重吐 `interrupt` 事件,不启动新一轮、不落库。

**本仓实测(langgraph 1.2.21,替代尚未落盘的 smoke)**:
- `ainvoke` 返回 `"__interrupt__": [Interrupt(value=...)]`,`out["__interrupt__"][0].value` 可取。
- `astream(stream_mode=["messages","updates"])` 的中断出现在 `updates` chunk:`{"__interrupt__": (Interrupt(...),)}`。
- `aget_state(config).interrupts` 是 tuple;`.next` 指向被中断节点。
- `Command(resume=v)` 从被中断节点从头重跑,`interrupt()` 返回 `v`。

**翻车与返工**:暂无。Context7 复核的官方语义与实测一致(resume 值成为 `interrupt()` 返回值、节点重启、checkpointer 存位)。
