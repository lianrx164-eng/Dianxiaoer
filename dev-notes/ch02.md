## 2026-11-13 阶段 2:项目基建与 DB 连接(Task 2)

- **用户关键原话**(就 Docker 缺失与 .env 红线的两次请示):"用本机 MySQL(推荐)";".env 允许新增两项"。
- **关键产出**:`uv add sqlalchemy[asyncio] asyncmy`(实装 SQLAlchemy 2.1.8 / asyncmy 0.2.18,Windows 有 wheel 无需编译);`docker-compose.yml`(按 plan 原样,留作他机);`app/config.py` 增 `database_url`/`test_database_url`;`.env` 与 `.env.example` 增两项;`app/db/base.py`(engine + async_session);`tests/conftest.py` 增 DB fixture(`_test_engine` 建 `mewhelp_test`、`db_session_factory` monkeypatch、`db_clean` TRUNCATE);`tests/test_db_conn.py` 1 passed,全量 30 passed。
- **拒绝与纠偏**:
  - Ruling——**Docker 未安装**,按用户拍板改用本机 MySQL 8.0(root/123456,服务 MySQL80),docker-compose.yml 照 plan 保留。
  - Ruling——本机 `mewhelp` 库已有 **246 会话/1438 消息/18 faq/20 工单** 的真实数据,且 schema 比权威 DDL 更演进(conversations 多 summary 字段、tickets 多「退款」枚举、另有 knowledge_chunks 等 5 张表):**不动它**,ch02 隔离到新建库 `mewhelp_ch02`(按权威 DDL 建表),`.env` 指向该库。成本:plan 里的库名 `mewhelp` 在本机不成立,README 需写明。
  - Ruling——连接串带 `?charset=utf8mb4`(Context7 对 SQLAlchemy async MySQL dialect 的推荐写法),避免中文 ENUM 值乱码。
  - Ruling——在 `sql/ch02-ddl.sql` 顶部补 `SET NAMES utf8mb4;`(spec 明言「DDL/seed 均自带」,用户给的 DDL 漏了);表定义未改。
  - Ruling——`pyproject.toml` 增 `asyncio_default_fixture_loop_scope/test_loop_scope = "session"`,见下。
- **翻车与返工**:
  - plan 的 conftest 建表逻辑有 bug:按 `;` 切分后再滤掉 `--` 行,但 DDL 注释里有半角分号(`…数据源;ch03 起…`),会把注释劈成两半导致 SQL 语法错误;且切分块以注释行开头,`startswith("CREATE TABLE")` 过滤永远为假。改为**先去 `--` 行再按 `;` 切分**。
  - pytest-asyncio 1.5 下 session 级引擎的连池连接被 function 级 loop 使用,报 `proactor 'NoneType' object has no attribute 'send'`;用上述 loop scope 配置把 fixture 与测试统一到 session 循环解决。
  - 照 plan 原样跑 `mysql mewhelp < ch02-ddl.sql` 时命中已有表(ERROR 1050),由此发现现有数据,转为隔离库方案。
